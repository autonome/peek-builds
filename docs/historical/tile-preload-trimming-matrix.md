## Plan corrections

The numbers below were produced by this audit script (reading every `.js/.mjs/.cjs/.ts/.html` file under feature directories). They differ from the hand-counts in `docs/historical/tile-preload-trimming-plan.md` in a few places. Noted here as follow-ups — do not retroactively change the plan.

- **`api.subscribe`**: plan said 198 calls across 71 files. Audit finds **184 calls across 27 features** (feature-count not file-count, so not directly comparable). Close enough; trivial.
- **`api.publish`**: plan said 147 calls across 58 files. Audit finds **145 calls across 27 features**. Close.
- **`api.datastore`**: plan said 144 calls across 19 files. Audit finds **142 calls across 12 features**. Close.
- **`api.shortcuts`**: plan said 24 calls across 10 files. Audit finds **24 calls across 10 features**. Matches.
- **`api.files`**: plan said 7 calls across 3 files. Audit finds **6 calls across 2 features** (editor, files). Close — editor has 4 (open, readFromPath, save, writeToPath), files has 2 (open, save).
- **`api.modes`** / **`api.closeWindow`**: both plan and audit agree on **0 sites** — safe to delete from the shim in Phase 4.
- **`api.context`**: plan said "~8 shim + ~15 non-shim" (23 total). Audit finds **18 total across 4 features** (editor, entities, groups, spaces). Of those:
  - Shim surfaces (`get`, `set`, `history`, `snapshot`, `windowsWithValue`, `windowsInSpace`): `get` (4), `set` (1), `windowsInSpace` via `getWindowsInSpace` (4) — note `api.context.getWindowsInSpace` is NOT in the shim (shim has `windowsInSpace`); this is a missing surface.
  - Non-shim surfaces (`setMode`, `watchMode`, `getMode`, `getWindowsInSpace`): `setMode` (9), `getWindowsInSpace` (4) — **13 non-shim calls**. No `watchMode`/`getMode` detected. The "~15 non-shim" estimate in the plan is close.
  - **Correction:** the shim method `windowsInSpace` is unused; features actually call `getWindowsInSpace` (missing surface).
- **`api.ipc.invoke`**: plan said 39 sites (features-manager only). Audit finds **39 calls in features-manager only**. Matches exactly.
- **`api.debug`**: plan said 34 files. Audit finds **28 references across 17 features**. Plan's file-count likely includes non-feature-scoped code (e.g., `app/`, `backend/`); the audit is feature-scope only.
- **`api.settings.getKey`/`setKey`**: plan said ~10 calls across 5 features. Audit finds a much higher total — `lex` (15: 7 getKey + 8 setKey), `widget-demo` (15: 7 getKey + 8 setKey), `editor` (4: 3 getKey + 1 setKey), `sheets` (3: 1 getKey + 2 setKey), `wonderwall` (2: 1 getKey + 1 setKey), `groups` (2: 1 getKey + 1 setKey), `tag-actions`/others (0). **Correction: getKey/setKey usage is significantly higher than plan estimated (~41 calls across ~6 features vs plan's ~10 across 5).**
- **`api.settings.getExtKey`**: plan said ~8 sites across 5 features. Audit finds **6 calls across 4 features** (features-manager 1, groups 3, spaces 1, tags 1). Plan row mentioned "groups/tags/entities" but entities does not call `getExtKey` in the audit (entities uses `api.settings.get` only).
- **Extended `api.window.*` missing surfaces**: plan said "~15 sites". Audit finds many more. Non-{open, close, getInfo} calls: `setTitle` (1), `list` (5: entities 1, groups 1, tags 1, windows 1, helpdocs effectively 0 but various others), `exists` (7), `show` (5), `hide` (3), `getFocusedVisibleWindowId` (6), `setOverlayFocusTarget` (2), `getBounds` (1), `setIgnoreMouseEvents` (2), `center` (1), `centerAll` (1), `fullscreen` (1), `maximize` (1), `setVisibleOnAllWorkspaces` (1). **Correction: ~37 call sites to missing window surfaces, not ~15.** The `windows` feature is the heaviest user (9 missing-surface calls); `spaces` (5), `groups` (5), `helpdocs` (5), `slides` (4), `pagestream` (3) also need migration.
- **`api.network`**: audit finds **0 call sites** across features, even though 5 features declare the `network` capability (entities, features-manager, feeds, lex, websearch, wonderwall). Network calls may use `fetch()` directly in the renderer rather than the capability-gated `api.network.fetch()` wrapper — worth a follow-up audit.
- **`api.filesystem`**: audit finds **0 call sites**. `files` feature declares the capability but uses `api.files.*` (the dialog shim), not `api.filesystem.read/write`.
- **`api.theme`**: audit finds **0 call sites** in any feature. No theme capability is used by tiles today.
- **`api.sync`**: audit finds **1 call site** (`sync/background.js` calls `api.sync.syncAll`). `api.sync` is NOT currently exposed in `tile-preload.ts` — this is a reference to a missing surface that would need adding if sync is migrated with capability gating. **Correction: treat `api.sync.syncAll` as a missing surface, not a shim.**
- **`api.pubsub.*` (method form)**: audit finds **0 call sites**. Every feature uses the top-level `api.subscribe` / `api.publish` shims rather than the strict `api.pubsub.subscribe/publish` form. This means the top-level shim removal in Phase 4 will require rewriting **all 27 features** that use pubsub at all. (The plan already marks this as "trivial" — audit confirms it's mechanical, just wide.)
- **Scopes**: audit detects **326 references to `api.scopes.*`** (GLOBAL, SELF, SYSTEM) across 27 features. Plan said "~145 refs" — **actual count is ~2.2× higher**.
